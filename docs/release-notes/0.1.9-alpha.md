## What changed in 0.1.9

This is a corrective release for defects found in 0.1.8 and in paths it exposed.

**Joining no longer loses images from multi-image FITS files.** 0.1.8 treated FITS as a guaranteed
single-frame format when counting a joined sequence. One FITS file can hold several image HDUs, so a
join of two two-image files reported two frames instead of four and the processor stopped once its
window was reached. FITS is now opened and counted; the single-frame shortcut is limited to readers
that provably return one frame (BMP, TIFF, PNG). Tests cover two multi-HDU files, ordering, a FITS/SER
mixture, and one-reader-at-a-time.

**A cached flat can no longer be corrected twice.** The "already corrected" state was a bare boolean,
reset whenever the flat-correction branch was skipped while the cached master survived. Running with
calibration, turning flat correction off, then on again could subtract the flat-dark a second time.
The state now lives with the cached master's identity (paths, frame counts, input signature and
flat-dark correction signature), and reuse requires the file to still exist. The three-run sequence is
tested: 104/156, uncorrected, then 104/156 again with no rebuild and no `-flat_dark_tmp`.

**Cancel during master building restores the form.** The in-process cancellation path now uses the
same transition as the engine-exit path, so Start Processing and the tabs come back in a `finally`
even if temporary-file cleanup throws.

**Declining Quit no longer deletes cached masters.** The close handler returned into the deletion of
the session directory after cancelling the close; it now returns immediately, and cached artifacts are
checked for existence before reuse.

**A non-zero engine exit is reported as failure.** The GUI treated only negative exit codes as errors,
so the CLI's exit 1 (runtime/calibration) and 2 (configuration) were displayed as COMPLETE. Only exit
0 is success; cancellation keeps its own end state.

**Saving the flat-dark master still works.** Suppressing `-flat_dark_tmp` for a corrected flat had
also removed the master the save operation needed. The GUI now writes the requested master itself
(`logs/pipp_master_flat_dark.tif`) from the `.tmp` it built, without restoring double subtraction.

**An explicitly named missing master stops the run.** Previously the loader returned no master and
processing continued uncalibrated. A named file that does not exist now raises a diagnostic naming the
path and switch, exits 2, and writes no science output. A bare `-dark`/`-flat`/`-flat_dark` with no
filename, and the GUI's corrected-flat handoff, remain valid.

**Master publication is transactional.** Existing masters are renamed aside before the new pair is
published (PGM first, authoritative `.tmp` last). If either rename fails, the new files are removed
and the backups restored, so the destination is either the complete previous pair or the complete new
pair, never a mixture. If restoring itself fails, the error names the kept backups.

## Known limits

- Median stacking retains at most 64 frames (759 MiB at 1920x1080 RGB); disk-backed tiled median is
  not implemented.
- Mean/sum/median final stacking remains a Core API capability, not a CLI or GUI control.
- A Bayer-marked selection is stacked as ordinary samples (`Bayer=None` on the result).
- Native master goldens come from identical inputs; unequal-frame fixtures are still missing.
