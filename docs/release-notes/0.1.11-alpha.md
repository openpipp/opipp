## What changed in 0.1.11

A correctness patch driven by an execution-based review of 0.1.10. Two of the fixes close paths that
could produce a silently wrong result; the rest make failures controllable and claims honest.

**Raw SER output now describes the frame it contains.** 0.1.10 corrected the CFA phase inside the
pipeline, but the SER header writer still copied the source file's ColorID. A horizontally flipped
8x6 RGGB capture therefore wrote correct pixels under a header that still said RGGB, where GRBG is
correct; flips, rotations, odd-origin crops and odd translations were all affected, and a binned image
kept a mosaic header after the lattice had been destroyed. The ColorID is now derived from the
delivered frame's pattern: RGGB 8, GRBG 9, GBRG 10, BGGR 11, None 0, colour 101. A sequence whose
frames disagree on phase is refused with a controlled error rather than written under one header.
Verified through the built CLI, not only tests: the flip case writes ColorID 9 with the expected
tile.

**Format failures can no longer escape as raw exceptions.** `FitsFormatException`,
`FitsTruncationException` and `BayerPhaseException` derive from `Exception` and were absent from the
decode-failure and CLI catch lists, so a corrupt FITS ended the process with `0xE0434352` instead of a
reported failure, and a mixed-CFA join crashed after correctly refusing the input. They now count as
per-input failures with a name and reason, the CLI maps every escaped format/calibration fault to a
documented exit code (2 configuration, 1 partial/runtime), and the last-resort handler deliberately
does not swallow cancellation.

**`-check` audits every image HDU.** It previously decoded only the first frame, so a file whose first
HDU was valid and whose second was truncated reported OK. It now walks the header chain, recomputes
each data offset and payload length from NAXISn/PCOUNT/GCOUNT/BITPIX, verifies the bytes are present,
and reports the image-HDU count without decoding pixels. Help documents this as structural validation
versus a full processing run.

**Quality weights no longer depend on storage order.** Frames were sorted into source order before
positional quality weights were assigned, so `-nr` or `-no_ram_buff` changed which ranks received
extra copies: the review's seven-frame case moved a mean from 95 to 44 from identical selected
inputs. Copy counts now attach to quality rank before any delivery reordering; default, `-nr`,
`-no_ram_buff`, both together, and spilled runs produce byte-identical masters (95 in that case).

**Final stacks keep identity metadata.** `FrameStacker.Result` dropped `SourceName`, so observer,
telescope and instrument fields were written empty. The first accepted frame's metadata is carried;
if sources disagree, the first frame's whole set wins (documented, no field mixing).

**The picker offers only what the engine can open.** JPEG, MOV/MP4/MKV and non-DNG camera RAW were
listed but could never be processed. The filter is now derived from the engine's own format set, a
stale `raw_file_extensions` setting can no longer re-admit unsupported types, DNG files are probed at
add time so compressed/tiled variants are rejected before a run, and rejections say why.

**Help matches behaviour.** `-avi_codec` documents DIB as the only implemented codec (1/2 are
rejected, with a compatibility note), and `-avi_quality` is 1..10 rather than 1..100. Documentation no
longer claims PGM or DNG as general read/write science formats: PGM is a calibration input, DNG is
read-only.

**Test honesty.** Four `UnitTest1` placeholders that asserted nothing are gone. GUI transcript cases
that need `samples/saturn30.ser` no longer return early and report a pass; they skip explicitly with
the missing path when the fixture is absent.

## Verification

- **926 tests**, 0 failures, nine projects (0 skipped locally; fixture-dependent cases skip loudly in CI).
- Parity unchanged: 27 compared, 27 matched, 2 deliberate differences, 0 gaps.
- Reproduced against the built CLI: flipped RGGB SER writes ColorID 9 with tile `[107,53;191,107]`;
  corrupt FITS under `-check` exits 2 naming the truncated header; mixed-CFA join exits 1 with a
  controlled explanation.

## Known limits

- Median stacking retains at most 64 frames; disk-backed tiled median is not implemented.
- Mean/sum/median final stacking remains a Core API capability, not a CLI or GUI control.
- A Bayer-marked selection is stacked as ordinary samples (`Bayer=None` on the result).
- Floating-point FITS is converted to the integer model without scaling; 0.1-0.9 collapses to 0/1.
- Native master goldens come from identical inputs; unequal-frame fixtures are still missing.
