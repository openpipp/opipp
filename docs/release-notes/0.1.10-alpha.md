## What changed in 0.1.10

A correctness patch: every fix below removes a way to get a plausible-looking but wrong or incomplete
result.

**8-bit FITS files are now padded correctly.** The writer emitted one byte per sample for 8-bit data but
padded as if it had written two, so the 2x2 mono8 case produced 5,756 bytes instead of 5,760. A
tolerant reader still opened the single image, but multi-image 8-bit files placed later headers at the
wrong offset (two written images read back as one). Padding is now derived from the bytes actually
written, and tests walk each header at its computed offset without relying on the reader.

**Bayer handling is one rule instead of three behaviours.** Debayered colour frames used to inherit the
raw mosaic marker, which made colour FITS output fail. They now carry no CFA pattern. An explicit
`-db=<pattern>` is applied before calibration and overrides container metadata, so an untagged mono
mosaic can be debayered and a wrong header can be corrected. Raw flips, rotations and odd-origin crops
recompute the phase from the mapping; binning and bilinear resize end the mosaic and clear it. A
sequence whose frames end up with different phases is refused with `BayerPhaseException` rather than
writing a header that lies.

**Partial runs no longer look complete.** A run that wrote frames and then failed on a later input
reports `PARTIAL FAILURE`, names the failing file, labels the output incomplete, and exits 1. The GUI
shows `PROCESSING INCOMPLETE` instead of claiming completion.

**`-check` does what it advertises.** It validates the command line, inputs, calibration masters,
geometry and output settings, prints the result, and exits 0 or 2 without creating an output directory
or any file. The help text records that the original engine treated `-check` as an alias of `-chk`.

**Cancellation deletes only its own files.** The cleanup used to delete every `*.tmp` in the chosen
output folder; with an existing folder that destroyed unrelated files. Cleanup now removes only paths
the run registered.

**Every AVI preset produces a file.** Two presets selected codecs the engine does not implement
(FMP4/MPEG-4 and ULRG/Ut Video) and failed at run time. Both now select uncompressed DIB, the codec
the engine writes, with the size implication visible.

**GUI calibration counts every image in a FITS file.** The file list counted each FITS path as one
frame and passed that as a build limit, so a two-image dark contributed one image and the master mean
was wrong. The list now probes the real frame count, and a full master build is not capped by a
display estimate.

**Saved flat and flat-dark no longer collide.** A mono flat was saved under the flat-dark name, so
requesting both left only one file (and the wrong one). Each master now has its own name.

## Verification

- **824 tests**, 0 failures, nine projects.
- Parity unchanged: 27 compared, 27 matched, 2 deliberate differences, 0 gaps.
- Checked from the packaged CLI, not only in tests: an 8-bit FITS output is 5,760 bytes (2880-aligned);

  1 with `PARTIAL FAILURE` and one clearly labelled incomplete frame.

## Known limits

- Median stacking retains at most 64 frames; disk-backed tiled median is not implemented.
- Mean/sum/median final stacking remains a Core API capability, not a CLI or GUI control.
- A Bayer-marked selection is stacked as ordinary samples (`Bayer=None` on the result).
- Native master goldens come from identical inputs; unequal-frame fixtures are still missing.
- Floating-point FITS is converted to the integer model without scaling; 0.1-0.9 collapses to 0/1.
