## What changed in 0.1.6

**The original project's branding is gone from the application.** The About box was a verbatim port
of PIPP's: it showed PIPP's logo, the original author's copyright line, a link to the PIPP site and
credits for dcraw, FFmpeg and NeuQuant. None of those components are part of OPIPP, and presenting
them misattributed this work and implied an endorsement that does not exist. The window now describes
OPIPP only, with our artwork, the GPLv3 notice, and an explicit non-affiliation statement.

Also replaced:

- the **application icon** (the shipped `app.ico` was PIPP's film-strip logo) and the icon embedded
  in the main form's resources, both now the project's ringed-planet artwork;
- the **assembly metadata** (`Copyright` and `Description` no longer describe the code as Chris
  Garry's reconstruction);
- the **update check**, which downloaded `sites.google.com/site/astropipp/version.txt` and sent users
  to PIPP downloads. It now queries this repository's GitHub releases and compares versions.

The window title is now read from the assembly's informational version, so it cannot drift from the
build again. A test scans shipped source for the old attribution and requires the application icon to
hash-match `docs/assets/opipp.ico`.

**Other fixes**

- The GIF colour-lookup cache is capped at 65,536 entries; palette bytes are unchanged (pinned by
  hashes recorded before the change).
- Cancelling during SER/AVI output preparation now stops promptly instead of reading the whole
  selection.
- `FrameStore.Dispose` always closes the backing stream, even when the writer flush throws.
- Two zero-frame containers can no longer count as a parity match, and repository-root discovery
  looks for `OPIPP.slnx`.
- README and roadmap contradictions about AVI/MJPEG, the `-gui` transcript and the parity case count
  are corrected.
