## What changed in 0.2.0

Final-image integration is now a first-class operation. Joining captures, building calibration
masters and integrating science frames are three separate things, and the third one is finally
reachable without writing code.

### User-facing

- **CLI:** `-stack=mean|sum|median` produces one final image. `-stack_coverage=crop|canvas` chooses
  whether the output is cropped to the region every frame can fill (default) or keeps the first
  frame's canvas. `-stack_subpixel=on|off` controls fractional registration (default on). These are
  OPIPP extensions; the original `pipp_core.exe` exits 127 on them.
- **GUI:** Processing → *Final image integration…* offers the same three choices and shows the
  current setting in the transcript when a run starts. Ordinary runs emit exactly the same switches
  and transcripts as before.
- **Result:** exactly one file per run, written under a staging name and moved into place only after
  success, so a cancelled or failed integration leaves nothing that looks finished.

### Registration and borders

- Each frame's alignment offset is applied by the integrator. The whole-pixel part is exact; the
  fractional part is bilinear, and mean, sum and median share one sampler so they register
  identically.
- Coverage is counted per pixel. `crop` intersects the valid regions (a bilinear tap loses a border
  column on the side it samples from) and returns that rectangle; `canvas` keeps the first frame's
  canvas and reports zero-coverage pixels rather than filling them with invented data.

### Precision

- Accumulation is `double`. `IntegrationResult.PrecisionSamples` exposes it: a mean of 100 and 101 is
  exactly 100.5 there. The delivered image is quantised to the input depth with half-away-from-zero
  rounding and clamping; sum clamps at the depth maximum. Float FITS output is not implemented yet.

### Median at scale

- Median up to 64 frames stays in memory. Above that, every frame is spilled once and the image is
  produced in horizontal bands, sorting each pixel's contributors per band. Memory is bounded by the
  band, not the selection, and the result is exact: 65 and 1,000-frame cases match an independent
  per-pixel reference. The scratch budget is declared and exceeded budgets fail clearly.

### Correctness around integration

- Mixed Bayer phases, mixed geometry or depth, a colour frame with a CFA tag, and non-uniform weights
  under median are all rejected before any sample, count or provenance changes.
- Contributors (source, weight, applied shift) and per-pixel coverage are reported with the result;
  the output frame keeps the contributing source's identity.
- Cancellation is checked per band and per frame read; no partial output or spill file survives.

## Verification

- **1,164 tests**, 0 failures across nine projects.
- Native parity unchanged: 27 compared, 27 matched, 2 deliberate differences, 0 gaps.
- Reproduced end-to-end from the built CLI: mean of a joined 5 and 6 writes 6; mean of 100 and 101
  writes 101; median of 10/20/30 writes 20; mixed-CFA join exits 1 with no file; unknown method exits 2.

## Known limits

- No sigma-clipped or robust rejection; every selected frame contributes.
- Alignment is subpixel translation only; no rotation, drizzle or local warping.
- Integration output is quantised to the input depth (double intermediate, integer delivery).
- Median above the cap trades speed for bounded memory; it is exact, not approximate.
- Surface-feature tracking remains 23/30 on one fixture; unequal-frame native master goldens are
  still missing.
