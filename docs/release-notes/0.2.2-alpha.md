## What changed in 0.2.2

This release is about evidence: real captures, measured memory, and the working path for raw Bayer
data. No integration arithmetic changed.

### Real-capture validation

Integration was run on captures that are not Saturn-2016 or synthetic:

| Capture | Object / date | Result |
|---|---|---|
| Slooh AVI, 49 extracted frames | Jupiter + Ganymede, 2011-09-08 | joined mean → one 640×480 colour image; visually clean disc and moon |
| Strata SER, 200-frame subset of 8,984 | Saturn, 2022-10-25 | raw CFA + centring **rejected** as designed; `-db` + mean → one 619×598 colour image in ~3 s, clean rings and globe |
| Strata TIFF | Jupiter, 2023-11-02 | conversion correct (IR685 green cast expected) |
| Wikimedia stills | Moon (2010) and Mars (2003) | PNG→FITS→PNG and PNG→TIFF round-trips correct |

Two real input gaps were found and are documented rather than hidden: the Slooh AVI is **I420**
(planar YUV), and an ffmpeg `rawvideo bgr24` AVI reports its first frame as truncated. Both are
rejected with clear messages; extracting PNG frames is the current workaround. See
`docs/validation.md` for sources, licences and commands.

### Debayer guidance

A raw mosaic can only move by whole pixels without changing its CFA phase, and centring commonly
produces odd shifts. The help section and every Bayer-phase error now say so and name `-db` /
`-db=<pattern>` and the GUI's "Debayer Monochrome Frames" option, instead of only saying "debayer".
A fixture-gated regression runs the real Saturn capture both ways: rejection without `-db`, one
correct colour image with it, and a plain 30-frame conversion as control.

### Measured memory

`tools/Opipp.IntegrationProbe` runs each configuration in its own process and samples peak working
set every 20 ms. Measured on this machine (i5-13600K, 128 GB, .NET 10.0.13):

| Case | Route | Peak working set |
|---|---|---:|
| 300 × 512×256 mono8 mean, spilled | streaming | 46 MB |
| 300 × 512×256 mono8 median, spilled | streamed | 89 MB |
| 100 × 1920×1080 RGB16 median | in memory | 2,476 MB |
| 200 × 1920×1080 RGB16 median, 4 GB scratch | tiled | 11,679 MB |

Two honest findings: the in-memory median holds **two** copies of the selection (2.5 GB for 1.2 GB
of frames), and the tiled route's process peak is dominated by allocation churn (6,800 temporary
full-frame buffers), even though live data is ~2.5 GB. The default 512 MiB scratch budget refuses
the 200-frame case before writing anything. `docs/memory.md` records all numbers and commands.

### Run-owned staging

Integration stages inside `<output>/.opipp-staging/<run-guid>/` and deletes that directory on
success, failure or cancellation. A later run removes stale GUID directories older than an hour;
nothing outside `.opipp-staging` is enumerated, so an operator's files are never at risk. The GUI's
stale comments about a flat `.integrating` file were corrected; it still deletes only registered
paths.

### Cancellation and restart

The GUI reused a single `Process` object for every run. After a cancel, that object's stdin pipe was
already disposed, so the next run could fail at launch with "The pipe is being closed" — a supported
workflow (cancel, then try again) broken by resource reuse. Each run now creates a fresh process,
restores the `SynchronizingObject` the designer had set (without it, engine callbacks arrive on pool
threads and the transcript verdict races the form), and a shutdown exception while a run is being
cancelled keeps the verdict CANCELLED instead of being re-labelled a start failure. The cancellation
test now uses a long-enough selection for Cancel to end the run, and its assertion reports the
engine's exit code, output and captured errors if it ever diverges.

## Verification

- **1,324 tests**, 0 failures, nine projects.
- Parity unchanged: 27 compared, 27 matched, 2 deliberate differences, 0 gaps.
- Real-capture outcomes reproduced from the built CLI; images inspected, not just exit codes.

## Known limits

- No sigma-clipped or robust rejection yet; that is the 0.3.0 milestone.
- In-memory median holds two copies of the selection; tiled median's process peak grows with
  allocation churn even though live memory stays bounded.
- AVI input: I420/planar YUV and ffmpeg rawvideo layouts are not supported.
- Integration output is still quantised to the input depth; no float FITS delivery.
- No lunar or solar **sequence** validation yet; Moon/Mars coverage is stills only.
