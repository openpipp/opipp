## What changed in 0.2.1

A correctness patch for final-image integration. Every fix closes a way to get a wrong image, destroy
someone else's file, or silently ignore a configured resource limit.

**Raw CFA frames are no longer averaged across colour sites.** Integration compared Bayer tags before
registration, but an odd-pixel shift moves the 2×2 mosaic to another phase, and bilinear sampling on a
raw mosaic blends four differently coloured sites. Each contributor's effective phase is now computed
after placement and after the output crop: the output is tagged at its actual origin, contributors that
disagree are rejected before any sample changes, and a fractional offset on a raw mosaic is refused
outright with a message pointing at debayering. (A single frame shifted by −1 is now correctly tagged
GRBG; two RGGB frames placed one pixel apart are rejected instead of averaged.)

**Integration no longer reloads the retained capture.** The pipeline used to materialise every selected
frame into a list before integrating, defeating the retention budget; median then spilled them again
while the full set stayed reachable. Frames are now read from the retention store one at a time (and
re-read per median band) with no frame held across calls. A 300-frame spilled selection peaks at about
2 MB of live objects instead of ~19 MB.

**Staging files are owned, not guessed.** The predictable `<name>.integrating<ext>` path could truncate
and then move away an unrelated existing file. Staging now uses a unique GUID name created with
`CreateNew`, and cleanup deletes only that exact path. A preseeded `.integrating` sentinel survives
success, failure and cancellation.

**The area of interest is applied after registration.** Cropping before registration threw away source
pixels needed inside the requested aligned crop (a 10×10 AOI came out 7×9 with 63 valid samples). The
AOI is now a request on the delivered canvas and is applied to the integrated result, giving the
requested 10×10 and 100 valid samples; a request that misses the overlap fails with both rectangles named.

**Median honours its in-memory threshold.** Every median selection was forced through the disk path,
ignoring `MaxRetainedMedianFrames`; with the default budget a 44-frame Full-HD RGB stack failed although
it is below the cap. Median now routes in memory when the count and a declared byte estimate fit, and to
the disk-backed path otherwise. Both routes produce identical pixels; the chosen route and estimate are
reported on the result.

**GUI integration settings are part of the option lifecycle.** Enabled, method, coverage and subpixel
are written to `.pof` files, restored on load (old files get explicit defaults), cleared by Reset
Options and restored by Undo Reset. Previously a reset run still emitted `-stack=sum`.

### Corrections to earlier claims

- "One file per run" was wrong: integration produces one file per batch input, or one per joined unit.
- "Median stays in memory up to 64 frames" was not true in production before this patch; it now is,
  subject to the byte estimate, with the disk path above it.
- A run where an input fails still publishes the accepted frames' integration as a labelled partial
  result with exit 1; final integration does not require every selected file to decode.
- A hard kill during output staging can still leave one uniquely named `.integrating` orphan, because
  the engine cannot run cleanup when the GUI kills it. It is never mistaken for a finished image, and
  the GUI deletes only files it owns rather than sweeping the directory.

## Verification

- **1,319 tests**, 0 failures, nine projects.
- Parity unchanged: 27 compared, 27 matched, 2 deliberate differences, 0 gaps.
- Reproduced against the built CLI: two RGGB frames whose centring places them one pixel apart now exit
  1 with the phase conflict named and write nothing; a static odd-shift case succeeds with the tag
  computed at the output origin; the 40×30 AOI case returns a 10×10, all-200 image; a preseeded
  `a.integrating.ser` survives an integrating run unchanged.

## Known limits

- No sigma-clipped or robust rejection; every contributing frame counts.
- Integration output is quantised to the input depth (double intermediate, integer delivery); no float
  FITS output yet.
- Raw mosaics reject fractional registration and phase-changing shifts; debayer to colour first.
- Subpixel translation only: no rotation, drizzle or local warping.
- Median above the in-memory caps is exact but slower, and scratch use still grows with contributor
  count at a fixed band height.
